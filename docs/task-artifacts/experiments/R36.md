## 结论

**❌ R36 判负（阴性确认）：根 `vercel.json` 对 api Project 同样无覆盖效果。**

机制与 R35 完全对称：api Project 的 Root Directory = `apps/api` ⇒ 项目配置从 `apps/api` 读取，仓库根的 `vercel.json`
既不是项目配置，也不覆盖任何 Project 级设置。

**与 R35 的交叉对照价值**：两个 Project 的 Root Directory **不同**（`apps/docs` vs `apps/api`），而根配置对**两者都无效**
⇒ 排除了「根配置只对某一个 Project 生效、从而造成交叉污染」这一残余可能。F38 的交叉污染面被**双向**关闭。

**诚实标注**：结构判定 + 等价验证，非 F38 原式复现。

## 关键发现

1. **【FINDINGS #30】F38 的交叉污染面被双向关闭**——R35（docs 侧变量 → 查 api project）与 R36（api 侧变量 → 查 docs project）
   互为对照，两个方向都是「无覆盖」⇒ 不存在「根配置只影响对方 Project」的机制。
2. **【FINDINGS #30】F38 与 F39 是两个独立失效面**——F39（同一目录反复 `vercel link` 的单槽覆盖）仍是真实风险，
