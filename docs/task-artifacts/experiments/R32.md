## 单变量重新界定（2026-10-30 拍板，采用「轴 B：debug 真实入场轴」）

> **本节为启动前拍板**（由 4 名子代理取证 + 主代理裁定），不是执行记录。原文上方「可选的单变量方向（待决策，本档案不预判）」**以此节为准**。

### 选定轴：**轴 B —— debug 真实入场轴**

把 `debug` 加入 `apps/docs/package.json` 的 `dependencies`（精确版本 `4.4.3`），使其**真正进入客户端依赖图**，从而让主题那条 `vite.optimizeDeps.include: ['debug']` 从**悬空声明**变为**真实声明**（此为该变量的自然后果，不算第二个变量）。

**改动面（唯一变量 = `apps/docs/package.json` 的 dependencies 增加一行）**：

```diff
--- a/apps/docs/package.json
+++ b/apps/docs/package.json
   "dependencies": {
     "@repro/shared-core": "workspace:*",
     "@repro/ui": "workspace:*",
     "@ztl-uwu/nuxt-content": "2.13.9",
+    "debug": "4.4.3",
     "h3": "1.15.11",
```

- 用**精确版本 `4.4.3`** 而非 caret：本仓纪律是精确 pin + lockfile 冻结；且 `debug` 不在 `experiments/control.json` 的 `docsDependencies` 管控键里，caret 漂移不会被任何契约捕获。
- **不建 `experiment.json`**：`tests/baseline-contract.test.mjs:39-48` 的 `assertDependencyGroup` 只遍历 `Object.keys(control.docsDependencies)` → `debug` 不在管控面；而 `allowedSafetyPatterns` 的 group 只允许 `nuxtConfig` / `pnpmWorkspace` → 「加一个未被管控的依赖」**无法在 experiment.json 里表达**。代价是**该变量对契约门不可见**，必须靠自证观察，不能靠契约绿灯。
- lockfile 由 `experiment-lockfile.yaml` 官方通道刷新（改 manifest 会命中其 paths 过滤器），**不手改 lockfile**。预期 lockfile 变化仅为 `apps/docs` importer 增一行 `debug: specifier 4.4.3 / version 4.4.3`——**复用同一 store 条目**（lock 中 `debug@4.4.3` 只有一个无 peer 后缀的解析条目），不产生第二份副本、不产生多版本。

### ⚠️ 关键约束：**该变量只能在 `nuxt dev` 观测，生产构建必然零差异**

实测依据：`node_modules/.pnpm/vite@7.3.6_*/node_modules/vite/dist/node/index.d.ts:822-828` 原文——

> _Deps optimization during build was removed in Vite 5.1. This option is now redundant……_

⇒ `vite.optimizeDeps` **在 build 期已失效**。**若只跑 build 不跑 dev，结论只能是「build 期 optimizeDeps 已失效（Vite 5.1+），该变量在生产链路上不可观测」，不能写成「debug 无害」。**

## 结论

✅ **verified / clean negative**——R32 完成（2026-10-30，轴 B「debug 真实入场轴」）：**变量真实生效，现象为零**。

1. **单变量真实生效（可证伪性已验证）**：把 `debug@4.4.3` 加入 `apps/docs` 依赖后，主题的 `vite.optimizeDeps.include: ['debug']`
   从**悬空声明变为真实声明** —— dev stderr 的 `Failed to resolve dependency: debug` **消失**，
   `deps/` 下**新增 `debug.js`（13951 B）**，`optimized` 键从 `errx` 变为 **`debug, errx`**。
   ⇒ 这条链路是**真实可观测**的，不是「观测点选错」。
2. **但功能影响为零**：首页 HTTP 200，**剥离 dev-only 日志块后两臂页面主体逐字节相同**（各 25680 B）；
   **零 ESM/CJS 入口错误**（`exports is not defined` / `does not provide an export named 'default'` /
   `Cannot use import statement outside a module` 全部 0）；**客户端产物无新增 chunk**（`debug` 无人 import ⇒ 无 chunk）。
3. **⇒ 结论与预期一致（F30 未复现）**：`debug@4.4.3` 安装态 `package.json` 实测 **`dependencies` 仅 `{ ms: "^2.1.3" }`**、
   **无 `exports` 字段、无 `module`、无 `type`** ⇒ 纯 CJS 且**不存在 exports map 入口歧义** ⇒
   三条经典 ESM/CJS 签名**在结构上不可能由 debug 自身产生**。**F30（browser module error 打断 hydration）在本拓扑下判为 clean negative。**
4. **「把 debug 拉进依赖」既不必要也无害**：它能消掉一条 dev 告警（好看），但**不修复任何功能**；
   且它会让 `debug` 进入客户端依赖图（增加 13951 B 预打包产物 + 一条传递依赖 `ms`）——
   ⇒ **不建议把「消除 optimizeDeps 悬空告警」当作修复手段**。
5. **⚠️ 悬空声明是系统性的，不是 debug 独有**：两臂均命中**同样 9 条**同类告警
   （`@nuxt/content > @nuxtjs/mdc > remark-gfm / remark-emoji / remark-mdc / remark-rehype / rehype-raw / parse5 / unist-util-visit / unified` ＋ `@nuxt/content > slugify`）。
   ⇒ 主题 `shadcn-docs-nuxt@1.1.9` 的 `vite.optimizeDeps.include` 是**一份按需罗列包名的历史清单**，
   在当前版本组合（Nuxt 3.21.2 / `@ztl-uwu/nuxt-content` 2.13.9 / Vite 7.3.6）下**整体滞后**；
   **单点治理 `debug` 只消掉 10 条里的 1 条**。

## 关键发现

1. **「悬空 optimizeDeps 声明」是一类症状，不是一个个案**：本仓实测 **10 条**（`debug` + 9 条 `@nuxt/content` 相关）悬空告警，
   全部来自主题 `shadcn-docs-nuxt@1.1.9` 的 `vite.optimizeDeps.include`（`nuxt.config.ts:96-98`）。
   ⇒ 任何「先修 `debug` 再说」的局部治理都会**低估问题面**；正确表述是「**上游主题的 optimizeDeps 清单与当前依赖组合脱节**」。
2. **`debug@4.4.3` 无 `exports` map ⇒ 不构成 ESM/CJS 入口歧义源**：安装态实测 `dependencies = { ms: "^2.1.3" }`、
   `main: "./src/index.js"`、`browser: "./src/browser.js"`、无 `exports`/`module`/`type`。
   ⇒ 「debug 是 ESM/CJS 冲突源」这一**原始假设在包结构层面即不成立**，与 R31-family 的 clean negative 结论**互相印证**。
3. **依赖图存在 ≠ 会被打包**：`debug` 进入客户端依赖图后，Vite 会为它生成 `debug.js` 预打包产物（13951 B），
   但**客户端产物里不会出现 debug chunk**——因为**没有任何源码 import 它**。
   ⇒ 「包在依赖图里」与「包进客户端产物」是两个不同的事实，验收时不可互推。
4. **dev-only 日志块会污染页面字节比对**：`data-nuxt-logs` 脚本块的内容随 dev 运行状态变化（本次两臂相差 1018 B）。
   ⇒ 任何「页面逐字比对」必须**先剥离该块**，否则会得出「页面内容变化」的假结论。
5. **探针路径错会被读成「现象不存在」**：首轮探针沿用错误的 vite 缓存路径（`.vite/deps`）→ 误报「metadata 不存在」；
   实际落点是 `node_modules/.cache/vite/client/deps/`。⇒ 与 FINDINGS #26 发现 4（计数恒 0 先怀疑判据）**同源**：
   **探针自证必须在采信「未命中」之前完成**。
6. **worktree 环境噪声必须同环境对照**：`.worktrees/r32` 自身带 6 条 `#app-manifest` 预转换错误（首轮 dev 观测已证），
   与主工作区不同类 ⇒ 若拿 worktree 当实验臂、主工作区当 control 臂，**噪声不可比**。
   ⇒ 本轮改用「detached worktree 释放分支 + 主工作区双臂对照」，代价是两次 `pnpm install`（各 6–8s）。
