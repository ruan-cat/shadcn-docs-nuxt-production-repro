## 单变量重新界定（2026-10-30 拍板，采用「轴 B：debug 真实入场轴」）

> **本节为启动前拍板**（由 4 名子代理取证 + 主代理裁定），不是执行记录。原文上方「可选的单变量方向（待决策，本档案不预判）」**以此节为准**。

### 选定轴：**轴 B —— debug 真实入场轴**

把 `debug` 加入 `apps/docs/package.json` 的 `dependencies`（精确版本 `4.4.3`），使其**真正进入客户端依赖图**，从而让主题那条 `vite.optimizeDeps.include: ['debug']` 从**悬空声明**变为**真实声明**（此为该变量的自然后果，不算第二个变量）。

**改动面（唯一变量 = `apps/docs/package.json` 的 dependencies 增加一行）**：

```diff
--- a/apps/docs/package.json
+++ b/apps/docs/package.json
   "dependencies": {
     "@repro/shared-core": "workspace:*",
     "@repro/ui": "workspace:*",
     "@ztl-uwu/nuxt-content": "2.13.9",
+    "debug": "4.4.3",
     "h3": "1.15.11",
```

- 用**精确版本 `4.4.3`** 而非 caret：本仓纪律是精确 pin + lockfile 冻结；且 `debug` 不在 `experiments/control.json` 的 `docsDependencies` 管控键里，caret 漂移不会被任何契约捕获。
- **不建 `experiment.json`**：`tests/baseline-contract.test.mjs:39-48` 的 `assertDependencyGroup` 只遍历 `Object.keys(control.docsDependencies)` → `debug` 不在管控面；而 `allowedSafetyPatterns` 的 group 只允许 `nuxtConfig` / `pnpmWorkspace` → 「加一个未被管控的依赖」**无法在 experiment.json 里表达**。代价是**该变量对契约门不可见**，必须靠自证观察，不能靠契约绿灯。
- lockfile 由 `experiment-lockfile.yaml` 官方通道刷新（改 manifest 会命中其 paths 过滤器），**不手改 lockfile**。预期 lockfile 变化仅为 `apps/docs` importer 增一行 `debug: specifier 4.4.3 / version 4.4.3`——**复用同一 store 条目**（lock 中 `debug@4.4.3` 只有一个无 peer 后缀的解析条目），不产生第二份副本、不产生多版本。

### ⚠️ 关键约束：**该变量只能在 `nuxt dev` 观测，生产构建必然零差异**

实测依据：`node_modules/.pnpm/vite@7.3.6_*/node_modules/vite/dist/node/index.d.ts:822-828` 原文——

> _Deps optimization during build was removed in Vite 5.1. This option is now redundant……_

⇒ `vite.optimizeDeps` **在 build 期已失效**。**若只跑 build 不跑 dev，结论只能是「build 期 optimizeDeps 已失效（Vite 5.1+），该变量在生产链路上不可观测」，不能写成「debug 无害」。**

### 预期结果（基于取证的事实预期，**不是**结论）

| #   | 观测点                                                    | 基线（main）                                                                    | 加 debug 后预期                                                                                                                             |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | dev server stderr                                         | `Failed to resolve dependency: debug, present in client 'optimizeDeps.include'` | **消失**                                                                                                                                    |
| 2   | `apps/docs/node_modules/.vite/deps/debug.js`（+ `ms.js`） | 不存在                                                                          | **出现**                                                                                                                                    |
| 3   | `.vite/deps/_metadata.json` 的 `optimized`                | 无 `debug`                                                                      | **含 `debug`**                                                                                                                              |
| 4   | 客户端产物 `apps/docs/.output/public/_nuxt/` chunk 列表   | —                                                                               | **应完全不变**（无 import ⇒ 无 chunk）；若出现 debug chunk ⇒ 说明有人真的 import 了它                                                       |
| 5   | 浏览器 console                                            | 无                                                                              | `exports is not defined` / `does not provide an export named 'default'` / `Cannot use import statement outside a module` **极可能出现不了** |

**信号 5 为何预期不出现（源码实锤）**：`debug@4.4.3` 的 `package.json` **无 `exports` 字段、无 `module`、无 `type`** ⇒ 纯 CJS 包，`main: "./src/index.js"`、`browser: "./src/browser.js"`，`src/` 下 4 个文件**无 `.mjs`**。因为**没有 `exports` map**，Node/Vite 解析只能回落到 `main`（浏览器侧再回落 `browser`）⇒ **不存在「双包导出名不一致」的入口歧义**，三条经典 ESM/CJS 签名均不可能由 debug 自身产生。

⇒ **预期结论为 clean negative**（与 R31-family 同级证据强度）：「把 debug 真实拉入客户端依赖图后，悬空声明消失、预打包产物出现，但**未复现** F30 的 ESM/CJS 入口冲突——因为 `debug@4.4.3` 本身没有 `exports` map，不构成入口歧义源。」

**若信号 5 真的出现** ⇒ 才是 F30 阳性复现，须记录 browser module error 与 hydration 状态（暗黑模式 / 侧栏交互），**不只截图 UI**。

### 决策记录（为何不选轴 A）

轴 A（只加依赖、不改主题声明）会使 `optimizeDeps.include: ['debug']` 仍为悬空 → dev 告警**不会消失** → 信号 1 不可观测，实验将无法区分「变量无效」与「观测点选错」。轴 B 让该声明变为真实，是唯一能同时产出信号 1–4 的最小变量。
