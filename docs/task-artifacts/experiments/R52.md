## 3. 结论（verified）

1. **断点（实测）**：Nuxt 4 把**主 bundle nitro 实例**的 buildDir 改写为 `apps/docs/node_modules/.cache/nuxt/.nuxt`（N3 恒为 `apps/docs/.nuxt`）——content 模块的 `devStorage["cache:content"].base` 由 `nuxt.options.buildDir` 解析（module.mjs `:261-264`）→ **base 随实例错位**。插桩铁证：第 1 实例 base = `.nuxt/content-cache`（读到预热 4 条），第 2 实例 base = `node_modules/.cache/nuxt/.nuxt/content-cache`（读空）。
2. **因果链（全部实测）**：预热（buildDir 改写前）落旧目录 → 主 bundle `_snapshot` 读新目录空 → **bundled 零条**（`.nuxt/snapshot` 两处均不存在 = 零数据不 mkdir）→ 生产运行时 `cache:content:parsed` 无数据 → **Content API 全空**（R45 现象完全解释，含 content-index.json 缺失同源）。
3. **假绿面（实测）**：prerender 期挂在读空实例上 → `cache.getItem` miss → `sourceBase`（`apps/docs/content` 绝对路径）不受错位影响 → 解析成功 → **页面渲染成功**（11 routes 全绿）——「构建全绿 + 内容库为空」的双面性由此而来。
4. **次级环节（实测 + 待深挖）**：prerender 期 runtime `setItem` 回写目标 = 新 buildDir 目录，但 `node_modules/.cache/nuxt/` 整体不存在 → **写丢失**，被 content `storage.js:163` 的 `.catch(() => {})` 吞——workerd 内 fs 写的确切去向（沙箱丢弃 / 相对路径重写）未深挖，**不影响主结论**。
5. **R45 未归因闭合**：R45「control 为何写 JSON 而 R45 写裸 markdown」= **不是 content 写入行为差异**（storage.js 两版逐字相同、预热行为同款），而是 **N4 的快照读取目录错位**——control 的 JSON（prerender 回写）被 `_snapshot` 读到，R45 的回写丢失且 `_snapshot` 读错目录。
6. **F50 立号**：新故障模式「Nuxt 4 buildDir 改写 × content v2 预热目录错位 → 快照空 → 内容库为空」独立编号 **F50**（failure-catalog）；上游双靶点：nuxt（buildDir 改写语义）+ @nuxt/content（预热/devStorage 未对齐 nitro 实际 buildDir）。
