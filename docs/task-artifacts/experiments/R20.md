## 关键发现

1. **方法论**：PowerShell 工具后台任务默认 120s 超时会强杀采样进程（RUN1 采样被截断，日志无 DONE）。长构建的资源采样必须显式加大后台 timeout（本轮 RUN2 用 400s 覆盖 169s 构建）并保留 deadline + stopfile 双兜底；判定采样完整性看日志尾行是否为 `DONE reason=...`。
2. **测量**：NFT 打包段资源轮廓 = WS 峰值 3565.3 MB + 单核口径 ~54% 持续 CPU，内存峰值出现在 NFT 段尾（build 结束前 9s）——若未来复现假卡死，该段是首要观测点。
3. **对照价值**：fresh install 态本身足以排除 R18/R19 首轮超时的"默认配置必然长尾"假设。
