## 2. 全局执行纪律（每个实验都必须满足）

1. **构建必须串行**：同一工作区禁止并发构建（会污染 `.output` / `.nuxt`，引入资源竞争噪声）。
2. **隔离而非删除**：需要清理产物时用同目录 `Rename-Item` 就地改名（`node_modules.stale-*` / `dist.stale-*`），不用 `Remove-Item`（运行时硬安全策略会拦截）。
3. **单变量**：每个实验只改一个变量；变量在执行命令里时，在档案中明确写「变量载体 = 执行命令」。
4. **build 绿 ≠ 通过**：必须实际启动 `.output/server/index.mjs`，先验 `Listening` 行，再做**响应体内容级断言**（复用 `pnpm probe:content`，13 项）。
5. **前置门**：每次开工前跑 `node_modules` 健康度体检（`.pnpm` ≈ 1209 / `nuxt.mjs` ✓ / `tsc` ✓）。
6. **失败可采信性**：首轮 `exit 1 + Invalid URL` 一律判废，按 SOP 干净重测；timeout 失败（exit 124）不算故障证据，必须记录实际 timeout 与退出码。
7. **不手改 `node_modules`**；不把 `node_modules` 问题当应用层 bug 去改业务代码。
8. **文档即时同步**：每个实验完成后**同一批提交**内更新 R{xx}.md + QUEUE +（如有）FINDINGS，禁止「分支落档即算完成」。
