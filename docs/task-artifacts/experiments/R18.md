### pnpm 对 `publicHoistPattern` 的警告原文

- 安装日志 `/tmp/r18-install.log` 全文检索 `publicHoistPattern|unknown|field|hoist|deprecated`：**无匹配**。
- **事实记录**：pnpm 10.33.0 对顶层 camelCase 字面量 `publicHoistPattern:` **未报任何 unknown-field 警告**，静默容忍。即：治理键检测**完全依赖契约测试的字面子串匹配**，pnpm 侧不提供任何校验信号——这是「治理键依赖 camelCase 字面量」的实锤证据（详见 FINDINGS #20）。
- ✝️ **事实订正（2026-10-30 受控实测，pnpm 10.33.0）**：原文括注「该键非 pnpm 合法 kebab 键 `public-hoist-pattern`」**表述方向相反**。实测：`pnpm-workspace.yaml` 的设置键**只认 camelCase**——`publicHoistPattern:`（camelCase）**被接受、零警告、且 public hoist 真实生效**；`public-hoist-pattern:`（kebab）会被 pnpm **显式 WARN 并忽略**（`The following settings in pnpm-workspace.yaml were ignored because they are not written in camelCase`）→ **kebab 拼写不产生 hoist 风险**。故「改用 kebab 即漏检」**不是**已实证漏洞；契约枚举 kebab 属**纵深防御**（2026-10-30 A2 已实施，`forbidden` 扩为 4 项）。

## 结论

✅ **verified** — R18 单变量（camelCase `publicHoistPattern:` 字面量）在契约测试中**预期判违**（「控制组不应包含未声明的危险配置 publicHoistPattern」），证明治理键检测链路对未声明 public hoist 敏感；同时实测 pnpm 10.33.0 对该 camelCase 字面量**零警告静默容忍**，确证检测完全依赖契约字面子串匹配。build 全程 exit 0（install 8s / build:packages 5s / docs build 181s / 峰值内存 3559 MB），但运行时 content 端点 200+404shell，与 F47 基线签名一致，印证 F18「build 绿 ≠ 验收」。首轮 exit 124（480s timeout）为长尾误判，本次 181s < 900s timeout 已消除。

## 关键发现

1. **治理键检测依赖 camelCase 字面量、pnpm 不提供校验信号**：R18 写入 `publicHoistPattern:`（camelCase），pnpm 10.33.0 静默接受、无 unknown-field 警告。检测该危险配置的唯一机制是 `tests/baseline-safety.test.mjs` 的字面子串 `text.includes("publicHoistPattern")`。（✝️ **2026-10-30 订正**：原文「若未来有人改用合法 kebab `public-hoist-pattern`，契约将**漏检**」**不成立**——kebab 拼写会被 pnpm 显式 WARN 并**忽略**，不产生 hoist 风险；camelCase 才是**唯一生效拼写**。契约已按**纵深防御**扩为双拼写枚举，4 项 `forbidden`。）
2. **F18 运行时印证**：build exit 0 不等于 content 端点可用；本实验三个端点中仅 `/` 为真实 HTML，content API 为 200+404shell，与 FINDINGS #9 的 F47 基线签名吻合。
3. **内存水位稳定 ~3.5 GiB**：docs build 峰值 3559 MB（10s 采样口径），与 FINDINGS #14 基线（3565/3599 MB）一致，排除 public hoist 对本实验内存水位的可观测影响。
