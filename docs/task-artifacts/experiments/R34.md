## 关键发现

1. **【部署 control 可用「只读核验」固化，不必重新部署】**——R34 的实验产物是「两个 Project 在无根 `vercel.json` 前提下部署成功且运行时内容真实存在」这一**状态**；该状态由既有部署持续承载，且可由 Vercel API（Project 设置 / 部署列表 / 构建日志）与自定义域名抓取（内容断言）**完整核验**。⇒ **对「部署态 control」类实验，先判定 control 是否已由历史部署固化，再决定是否消耗额度重部署**——这是本仓部署额度约束下的通用省钱路径。
2. **【单槽绑定（F39）的可核验形式】**——除 `project.json` 外，`.vercel/` 目录下**不应存在第二个 `project.json`**；本轮实测两个目录均只有 1 个 ⇒ 单槽成立，且该判据**不需要任何云端写操作**即可验证。
3. **【自定义域名是绕过 SSO 的公网冒烟入口】**——两个 Project 的 SSO 为 `all_except_custom_domains` ⇒ `…docs.vc.ruan-cat.com` / `…api.vc.ruan-cat.com` 可直接抓取并做**内容断言**，无需 `vercel curl` 或临时 share link。
4. **【api 的运行时指纹可从公开端点直接读出】**——`/v1/runtime` 直接返回 `{"runtime":"nitro","generation":"nitro3-h3v2","node":"v22.23.4","platform":"linux"}` ⇒ 云端 api 的**世代（nitro3 + h3 v2）与 Node 版本**可被外部观测，不必再靠部署日志推断。
