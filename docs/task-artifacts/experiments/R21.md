## 结论

✅ **trace:false 在 Windows 构建链有效且构建大幅加速**（79.8s vs R20 冷态 213s，快 ~133s），exit 0，无超时。**但机制判读与设计预期相反**：关闭 trace 后 `.output/server/node_modules` 拷贝层确实消失（产物 16.6MB→8.2MB，nitropack 源码 `trace === false → external: true` 且跳过 NFT 追踪），**F26 缺包链未触发**——实测产物 chunks 零裸导入（静态 from / 动态 import() / require（） 三类扫描全空），说明本仓 docs 构建链在 externals 插件之前已将全部运行时依赖 inline 进 8.2MB bundle，trace 拷贝层对运行时是冗余的。孤立环境（/tmp，`import('ufo')` 报 ERR_MODULE_NOT_FOUND 证明环境无依赖可解析）三断言 200 且内容正确。

## 关键发现

1. **测量**：NFT trace 段是 R20 冷态 213s 中的最大耗时块——trace:false 后冷态仅 79.8s（差异 ~133s 与 R20 相位分析"启动+NFT+收尾 ~161s"量级吻合）。
2. **机制**：本仓 docs 站（Nuxt 3.21.2 + nitro-server 桥接）的 server 依赖在更早构建阶段已全量 inline（产物零 bare import），`externals.trace` 控制的拷贝层不参与运行时依赖供给——F26 缺包链风险仅存在于"产物含裸导入"的配置形态，本仓当前形态免疫。
3. **判读警示**：`.output/server/node_modules` 是否存在**不能**作为产物自包含的判据；应以孤立环境运行 + 裸导入扫描为准。R20 的 16.6MB 中 ~8.4MB 拷贝层对本仓为纯冗余。
4. **平台注记**：sharp win32-x64 binaries WARN 在 R21 构建中出现（`[@nuxt/image] WARN sharp binaries for win32-x64 cannot be found`），与本次单变量无关，属环境既有告警。
