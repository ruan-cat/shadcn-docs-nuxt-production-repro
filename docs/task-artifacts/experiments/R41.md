## 关键发现

1. **「删 lockfile fresh resolve」在本仓是一个近乎零风险的实验**——直接依赖漂移面为 0，因 4 个 caret 全在根 devDeps 且运行时依赖全部精确 pin + override 钉死。这解释了为何 CI 的 `fresh-resolution.yaml` 一直是绿的。
2. **但传递依赖差异高达 562 项**（286 项同名不同版本 + 276 项包名集合增删），且含 `@floating-ui/vue` 1.x → 2.x 的**主版本跳跃**、以及 `@nuxt/kit` 4.5.2 → 4.6.3 的 minor 漂移。**若将来把某个 caret 引入运行时依赖链，或解除 root overrides，漂移面会立刻从 0 变为非 0。**
3. **root `pnpm.overrides` 与 `pnpm-workspace.yaml` 的 packageExtensions 精确 key 之间存在脆弱耦合**：精确 key（`@ztl-uwu/nuxt-content@2.13.9`、`nuxt-og-image@5.1.9`）之所以生效，靠的正是 override 把版本钉死。**一旦 override 被解除（R05/R03 的变量），精确 key 失配 → h3@1.15.11 不再注入 → F47 第一层复发。** 本次实测证明该耦合当前成立。
4. **`nitro@3.0.260610-beta`（精确但 prerelease）未漂**——这是本仓唯一「可能是运行时直接依赖漂移点」的候选，实测排除。
5. **`fresh-resolution.yaml` workflow 只给原料，不给结论**：它采集 fresh lockfile + 3 份探针输出，但**不做与 committed lockfile 的 diff、不 build、不冒烟**，且 `retention-days: 7`。本实验的 diff 与归因由 R41 自身产出——**该 workflow 可作为执行载体，但不能替代实验**。
6. **契约不校验 lockfile 内容**：`tests/` 下 5 个测试文件均不读 `pnpm-lock.yaml` 内容（`ci-contract.test.mjs` 只读 workflow 文件字面）。⇒ fresh resolve 出的 lockfile 不会撞红任何契约，**漂移检测必须由实验自身产证据**。
