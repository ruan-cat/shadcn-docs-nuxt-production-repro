## 变量的重新界定（关键）

原档案写「preserve symlink vs dereference 对照」。本轮核实：

| 候选含义                                     | 是否是 Vercel 侧可切换的变量                                                                                            | 依据                                                             |
| -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| `vercel.json` 里的 `preserveSymlinks` 键     | **否**——官方 `vercel.json` 属性表**无此键**                                                                             | Vercel 官方文档「project configuration」属性表；官方 JSON Schema |
| `vercel build` 的 `--preserve-symlinks` flag | **否**——build 的选项只有 `prod` / `environment` / `target` / `output` / `yes` / `standalone` / `deployment` / `project` | 本机 `vercel build --help`（CLI 58.11.0）实测输出                |
| `@vercel/nft` 的 `preserveSymlinks` 选项     | **否**——`NodeFileTraceOptions` 无此字段，nft 默认 realpath（即 dereference）                                            | 上游源码                                                         |
| `NODE_OPTIONS=--preserve-symlinks`           | **是**，但它是 **Node 运行时选项**，不是 Vercel 构建选项                                                                | Vercel Node runtime 高级配置文档                                 |
| **`vercel build --standalone`**              | **是**——Vercel 侧真正可控的 symlink 变量                                                                                | 上游 commit `c4667d3`                                            |

⇒ **Vercel 侧真正的变量是 `vercel build --standalone`（保留 package-manager symlink）vs 非 standalone（跳过/解引用）**；
运行时侧再叠加 `NODE_OPTIONS=--preserve-symlinks`（需在 functions 配置或 env 注入）。

上游行为依据（子代理取证）：上游 commit `c4667d3` 原文——「For `--standalone`, package-manager symlinks are now
**preserved** rather than skipped」（否则目标在子目录外被跳过 → 运行时 `Cannot find module 'hono'`，PIPE-6621）；
该修复先 gated 于 `VERCEL_RESOLVE_ROOT_DIRECTORY=1`（vercel@54.18.7），后在 vercel@54.21.0 默认开启
（仅当 workspace 声明该目录为成员包）。本机 CLI **58.11.0** 已含该修复。

## 结论

**❌ R38 判负（阴性确认）+ 原变量不可执行。**

1. **原变量（`preserveSymlinks` 作为 Vercel 配置）在 Vercel 侧不存在**——不是 `vercel.json` 的键、不是 `vercel build` 的 flag、
   不是 `@vercel/nft` 的选项。⇒ 原实验定义**无法按字面执行**，必须重新界定为
   「`vercel build --standalone` vs 非 standalone」+「运行时 `NODE_OPTIONS=--preserve-symlinks`」。
2. **当前部署形态下不构成故障**——本仓 docs 确实依赖两个 workspace 包（symlink 形态，指向 Root Directory 之外的
   `.pnpm` 虚拟 store），正是上游 PIPE-6621 的风险面；但 R34 实测云端部署 READY、运行时内容断言**全通过**
   ⇒ **当前 symlink 处理没有造成任何可观测故障**。

**诚实标注**：本结论证明的是「当前形态下无故障」，**不是**「standalone 与非 standalone 在本仓等价」
（后者需要两次真实 `vercel build` + 产物比对，本轮未做——它的判据价值低于本仓已有的运行时断言）。

## 关键发现

1. **【FINDINGS #31】`preserveSymlinks` 不是 Vercel 的开关**——它在 Node 运行时层（`NODE_OPTIONS`），
   而 Vercel 构建层对应的开关是 `--standalone`。把二者混为一谈会导致「照着写一个不存在的键」然后误判实验无效。
2. **【FINDINGS #31】本仓的 symlink 风险面是真实的，但当前未触发**——
   `apps/docs` 的 `@repro/shared-core` / `@repro/ui` 是 `workspace:*` 依赖，在 pnpm 下是**指向 Root Directory 之外**
   `.pnpm` 虚拟 store 的 symlink，正是上游「symlink 被跳过 → 运行时 `Cannot find module`」的触发条件；
   CLI 58.11.0 已含上游修复（54.21.0 默认开启），且 R34 的云端运行时断言证明**当前未触发**。
   ⇒ 这是**需要监控的脆弱面**，不是**已发生的故障**。
3. **【FINDINGS #31】F41（Windows 本地与 Vercel Linux 的 symlink 行为差异）本轮未被单独验证**——
   本仓 CI 已有 Linux job 覆盖生产构建与 artifact smoke，可作为后续观察点；本轮不强行扩实验范围。
