## 结论

✅ **verified**——R44 完成（2026-10-30）：**并行构建在本仓当前拓扑下无收益、也无资源竞争**。

1. **并行确实发生**（不是"没跑成"）：200ms 粒度进程追踪抓到 `OVERLAP 18:29:57.851 nitro=2 nuxt=2 total=4`，
   最大并发本仓 node 进程数 **4**（2 × pnpm wrapper + 1 × nitro + 1 × nuxt）。
2. **墙钟未变快**：并行 159.5s（定案轮）/ 163.1s（旁证轮），对比串行 R42 159.2s + api 1.9s = 161.1s、R43 154.7s + 1.9s = 156.6s
   —— **并行不更快**（并行总墙钟由 docs 的 ~155–160s 独占，api 的 ~2s 几乎无法被"藏"进去）。
3. **峰值 WS 未叠加**：3619.7 MB（定案轮）/ 3589 MB（旁证轮），与 R23 基线 3599.4 MB 同量级（+0.56% / -0.29%），
   远非「两构建 WS 之和」；**重叠期最大同时 WS 仅 418.6 MB**。
4. **原因明确**：api 构建体量极小（`Server built in 51ms`、产物 62.1 kB / 62116 B、耗时 ~2s），与 docs 的 ~155s
   **几乎无重叠窗口** → F43 担心的「资源竞争与缓存写入干扰」在本拓扑下**未发生**（null 结果）。
5. **产物等价与串行轮同签名**：api 侧逐字节相同；docs 侧与 R42/R43 的残差**恒为同一组 6 个文件**，
   全部可归因于构建内生非确定性（content `buildIntegrity` 指纹、Nuxt `buildId` UUID 及其 chunk 名级联、
   lucide 图标 JSON key 序 / 模块条目枚举序）——**字节相同不是可达门，只能判内容等价**（依据 FINDINGS #23）。
6. **方法论缺陷已登记**：首轮采样器的 `repoCount` 判据用 `Get-Process` 的 `.Path`（= 可执行文件路径 `node.exe`，
   **不含命令行**）⇒ 在本机**恒为 0**，正是"并行确实发生"证据缺失的直接原因；靠
   `Get-CimInstance Win32_Process` + `.CommandLine` 的进程追踪（`proc-trace.ps1` / `race-detect.ps1`）才补上 `OVERLAP` 证据。

## 关键发现

1. **计数恒 0 时先怀疑判据、再下结论**（本轮最重要的方法论教训）：`repoCount` 用 `.Path -like '*shadcn-docs-nuxt-production-repro*'`
   永远命中 0——因为本机 node 装在仓库之外（`D:\store\nvm-desktop\22.23.1\node.exe`、`C:\Users\pc\.nvmd\bin\node.exe`），
   `.Path` 是**可执行文件路径**而非命令行。同一口径的 CIM 版（按 `CommandLine` 过滤）立刻给出 `cim_repoNodeCount=2`，
   200ms 版进一步给出 `nitro` 与 `nuxt` **同刻并存**的 `OVERLAP` 行。若沿用错误判据，会把「没采到证据」误判成「没发生」。
2. **`r44b` 是 F36 孤儿进程的真实样本**：脚本只等待 api 就记录墙钟（`parallel_wall_s=1.8` 是假值），
   并把 docs 构建留成后台孤儿进程。教训：**并发采集脚本必须等待全部子进程**，
   且墙钟必须在**所有**子进程结束后再落笔；孤儿进程按"轮询等待自然结束"处置，不无差别杀 node。
3. **并行在本仓无收益的根因是拓扑，不是调度**：docs 构建独占 ~155s 且内存峰值 ~3.6 GB，api 构建 ~2s 且产物 62.1 kB
   ⇒ 二者既无时间重叠（重叠期最大同时 WS 418.6 MB）也无资源竞争；**除非 api 侧体量显著上升**，否则并发化没有收益空间。
4. **内存水位由构建图决定，与执行次序/并发度无关**：R42 3619.2 / R43 3580.9 / R44 3619.7（+ 旁证 3589、3560）MB，
   全部落在 R23 基线 3599.4 MB 的 ±10% 带内，与既有结论（R24「水位由构建图决定，非堆上限」）一致。
5. **字节相同不是可达门**：本仓 fresh 构建**内容幂等、字节非幂等**（构建指纹 + 枚举顺序不确定性，FINDINGS #23）；
   三轮之间只能判**内容等价**（分层判据），字面「路径集合 + 排除 volatile 后哈希完全一致」在 docs 侧**结构上不可达**
   （161 个 `public/_nuxt/<contentHash>.js` 的文件名本身由指纹派生，且 chunk 互相引用兄弟 chunk 名 → 级联）。
