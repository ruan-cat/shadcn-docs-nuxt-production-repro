### F20 爆炸半径：hoisted 破坏 `.bin` shim 解析（核心发现）

1. **install 失败根因**（`/tmp/r19-install.log`）：
   ```plain
   . prepare$ simple-git-hooks
   . prepare: Done
   apps/docs prepare$ nuxt prepare
   apps/docs prepare: Error: Cannot find module 'D:\...\apps\docs\node_modules\nuxt\bin\nuxt.mjs'
   ```
   机制：`nodeLinker: hoisted` 下 pnpm 将 bin 提升到根 `node_modules/.bin`，但**不在 hoisted 后的 `.pnpm/<pkg>/node_modules/<pkg>/bin/` 内落地 `bin/<cmd>.mjs`**；而 `apps/docs/node_modules/.bin/nuxt` shim 解析 `../nuxt/bin/nuxt.mjs`（标准 node bin 相对路径），该文件在 hoisted 布局下缺失 → `nuxt prepare` 失败 → `pnpm install` exit 1。
2. **build:packages 同样失败**（`/tmp/r19-buildpkgs.log`）：`Cannot find module '.../packages/shared-core/node_modules/typescript/bin/tsc'`——**证明该破坏是系统性的，非 nuxt 特例**：hoisted 使所有经 `../<pkg>/bin/<cmd>` 相对路径解析的 CLI 全部失效。
3. **docs build 在 `prebuild: nuxt prepare` 直接失败**（exit 1，2s），从未进入真实构建阶段——故 R19 的「构建图放大 / 峰值内存」无法按 spec 预设测量：build 根本没跑起来。

### 运行时冒烟（被 hoisted 构建失败阻断）

- R19 的 docs build 失败，`apps/docs/.output/server/index.mjs` 当前存在但为 **R18 遗留产物（mtime 08:32，非 R19 构建）**，不代表 R19。
- 尝试启动 server 报 `EADDRINUSE: address already in use :::3000`——端口被孤儿进程 PID **23716**（`node.exe`）占用（CreationTime 08:34:11，系 R18 冒烟启动的 server；此前 `kill $SRV` 的 `$!` 捕获的是 bash 子 shell PID 而非 node PID，未真正杀掉，印证 FINDINGS #15 孤儿进程风险）。
- 已 `Stop-Process -Id 23716 -Force` 清理，端口 3000 释放（确认 `PORT3000_FREE`）。
- **结论**：R19 无自身构建产物，运行时冒烟不可执行；其「build 绿≠验收」在 R19 升格为「build 直接失败」——这是 F20 爆炸半径的最强证据。

## 结论

✅ **verified** — R19 单变量（`nodeLinker: hoisted`）在契约测试中**预期判违**（「控制组不应包含未声明的危险配置 nodeLinker: hoisted」），治理键检测链路对 hoisted 敏感；**同时 F20 爆炸半径被实锤且严重程度超出 spec 预设**：

- spec 预设「hoisted 全量重装 12m+」未复现——**warm store 下重装仅 21s**（1200 包全 reused、0 下载）；首轮 exit 124（480s）是冷 store 下的长尾，非 hoisted 固有代价。
- **真正危险是 hoisted 破坏 bin 解析**：install（nuxt prepare）、build:packages（typescript bin）、docs build（prebuild nuxt prepare）**全部 exit 1**，根因一致——hoisted 布局未落地 `.pnpm/<pkg>/node_modules/<pkg>/bin/<cmd>.mjs`，而标准 `.bin` shim 经 `../<pkg>/bin/<cmd>` 相对路径解析失败。这是系统性的工具链断裂，使整个 workspace 在 hoisted 下**不可构建**。
- 因 build 从未执行，docs 构建期峰值内存仅 2011 MB（baseline node 进程水位，非真实构建水位；R18 真实构建峰值 3559 MB 可作对照）——「构建图放大导致内存上升」的预设在 R19 无法成立，因为构建被 hoisted 提前阻断。
- 运行时冒烟被阻断（无 R19 产物 + 端口孤儿），进一步证明 F20 不是性能问题而是可用性灾难。

## 关键发现

1. **hoisted 致命面 = 工具链 bin 解析断裂（F20 实锤）**：`nodeLinker: hoisted` 下 pnpm 仅提升 bin 至根 `.bin`，不保证 `.pnpm/<pkg>/node_modules/<pkg>/bin/<cmd>.mjs` 存在；所有依赖 `node_modules/.bin/<cmd>` shim → `../<pkg>/bin/<cmd>` 相对解析的 CLI（nuxt、typescript 等）全部 `MODULE_NOT_FOUND`。install 与 build 双双失败。
2. **「12m+ 重装」是冷 store 假象**：warm store 下 hoisted 重装 21s 即完成，与默认 linker 量级相当；首轮 exit 124 是 timeout 预算不足 + 冷 store，非 hoisted 固有慢。
3. **孤儿进程盲点（FINDINGS #15 再证）**：R18 冒烟 `kill $SRV` 因 `$!` 捕获 bash 子 shell PID 而未杀掉 node server，导致端口 3000 被占用至 R19 才被发现；F36 按 `Path like '*repo*'` 过滤无法捕获（node.exe 在 store 路径），须靠端口监听检查兜底。
4. **构建图放大假设不成立**：因 hoisted 直接阻断 build，无法测出「构建图放大→内存上升」；能确认的是 hoisted 在更早期（prepare 生命周期）就已让构建不可能。

## timeout 放大记录

- 首轮（待重测起因）：install/build 合设 timeout 480s → exit 124（长尾/冷 store 超上限，非真实故障）。
- 本次重测：`install` 设 Bash 超时 1500000ms + 内部 `timeout 1500`；`build:packages` / `docs build` 各设 `timeout 900` + Bash 超时 900000ms。实际 install 21s / build:packages 2s / docs build 2s，均在配额内——**未因 timeout 截断**，失败纯因 hoisted 破坏工具链。内存采样器独立后台运行（stopfile 控制，deadline 900s）。
