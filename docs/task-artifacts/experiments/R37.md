## 结论

**❌ R37 判负（阴性确认）：「子包 `.vercel/output` 搬运到 repo root」不是 Vercel 支持的路径，CLI 不会识别该位置的产物。**

双向对照（同一 Project 绑定、同一份伪造 Build Output，只改落点）：

| `.vercel/output` 位置                | `vercel deploy --prebuilt --dry` 的行为                                                      | 判读                                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| repo root（搬运位）                  | `Error: The provided path "…\vc-probe-r37\apps\docs" does not exist.`                        | CLI **按 Project 的 Root Directory 定位**，搬运位根本没被看                          |
| `apps/docs/.vercel/output`（官方位） | `Error: The "--prebuilt" option was used, but no prebuilt output found in ".vercel/output".` | CLI **定位到了官方位**，但判定内容不完整（本次是伪造的最小产物，缺 `functions/` 等） |

⇒ **`vercel deploy --prebuilt` 只认 `join(cwd, project.rootDirectory, '.vercel/output')`**；把子包产物搬到 repo root
既不会被识别、也不会产生「跨 app 污染」——因为搬运位**根本不是候选路径**。

上游事实一致：`vercel build` 默认写 `join(cwd, project.rootDirectory, '.vercel/output')`，
`deploy continue` 同样查找该路径。

**F40 的四问逐条判读**：

| F40 子问                      | 判读                                                                                                                                                             |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 旧产物是否清理                | **CLI 侧已内置**：`vercel build` 会先 `fs.remove(outputDir)`；且 `--output` 非默认时**同时删默认目录**。搬运方案**不会**引入额外残留——因为它压根不被使用         |
| symlink 是否保留              | 见 R38（同一变量族，单独定案）                                                                                                                                   |
| dereference 是否必要          | 见 R38                                                                                                                                                           |
| 输出路径是否被另一个 app 污染 | **否**——搬运位不是候选路径，两个 Project 的产物互不干涉；跨 app 污染的真正风险面是 `includeFiles` / `outputDirectory` 指向别的 app，与 `.vercel/output` 落点无关 |

## 关键发现

1. **【FINDINGS #31】`.vercel/output` 的落点由 Project 的 Root Directory 决定，搬运到 repo root 是无效操作**——
   「搬过去再部署」这条路在 CLI 层就不成立，不存在「搬运后跨 app 污染」的中间态。
2. **【FINDINGS #31】F40 记录的四问里，「输出路径被另一个 app 污染」在当前架构下不成立**——
   真正的跨 app 污染面是 Project 设置里的 `includeFiles` / `outputDirectory`（项目级、只影响自己），
   与 Build Output 的物理落点无关。
